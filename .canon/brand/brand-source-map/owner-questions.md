# Primkit Owner Questions

## Mode Context

This is archaeology mode. The current source map already records confirmed product facts, current de facto site usage, rejected directions, and missing production decisions.

These questions are only owner-level judgment calls that the supplied sources cannot settle. They do not ask the owner to confirm current de facto copy, robot usage, social preview, terminal proof, or token values; those belong in the decision emission flow.

## Questions For The Owner

| # | Question |
| --- | --- |
| 1 | Should the first brand directions speak more to individual developers using agents day to day, or to teams standardizing agent workflows? |
| 2 | When the references compete, which should lead: SQLite durability, Git inspectability, ripgrep sharpness, Tailscale clarity, Fly.io confidence, or Unix composability? |
| 3 | How austere can Primkit feel before it becomes too cold or unfinished? |
| 4 | How far may visual directions evolve from the current navy/cyan robot system while still preserving its equity? |
| 5 | Should supporting visuals stay mostly terminal-led, or may directions add diagrams, screenshots, and icons when they clarify the primitives? |
| 6 | Should final typography feel more like a system manual, developer docs, or a modern infrastructure product? |
| 7 | Should demo GIF/MP4 proof become production marketing material, or remain supporting README/demo material? |
| 8 | Are there any additional brands, styles, or phrases that should be off-limits before directions are generated? |

## How Answers Are Used

Answers will guide downstream work this way:

- `brand-foundation` uses audience, tone, and austerity answers to shape the final voice system and cross-surface application rules.
- `brand-directions` uses reference-weighting and off-limit answers to generate direction options without drifting into rejected territory.
- `brand-visual-identity` uses visual-evolution, support-visual, typography, and demo-media answers to set the exploration range for identity and asset work.
- `brand-decisions` records any explicit owner approval or rejection that should become a consolidated decision.

Factual asset provenance, licensing, source-file availability, accessibility checks, and production export rules still require separate evidence or downstream validation.
