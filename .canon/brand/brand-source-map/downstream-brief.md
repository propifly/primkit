## Source Limitations

- Current site files are strong operating evidence, not final brand authority.
- Current copy, proof mode, robot use, social preview, and color tokens are de facto until consciously confirmed or changed.
- The token JSON and CSS are explicit provisional evidence; do not silently canonize them as the final color system.
- All supplied image, GIF, and MP4 files are export-only or reference-only evidence. No editable logo master, social-preview template, source package, license record, or approval record was supplied.
- Binary visual evidence was only partially readable. Do not infer logo geometry, color correctness, animation quality, accessibility, or licensing from pixels alone.
- Inspiration references were named by the owner but not externally audited.
- The requested `brand-family-contract.md` and `brand-id-contract.md` files were not discoverable in this workspace; the supplied task/domain contract text governed this pass.

| `DECISION:audience-ai-agent-developers` | Primary audience is developers and teams using AI coding agents; secondary audiences are agentic environment builders and multi-agent workflow operators. |
| `DECISION:promise-state-survives-session` | Lead impression should center on agents having state that survives the session. |
| `DECISION:claims-no-server-stack` | Support the promise with four CLIs, four SQLite files, and no server, SDK, API key, Postgres, Redis, or daemon. |
| `DECISION:positioning-explicit-local-operating-model` | The operating model is explicit, local, inspectable, scriptable, replayable file and command use. |
| `DECISION:tone-durable-explicit-calm` | Tone should feel durable, explicit, serious, local, inspectable, calm, and CLI-native; it should speak to agent workflows without feeling like disposable AI hype, and the durable local infrastructure story should outlast the current agent tooling cycle. |

| `DECISION:vocabulary-allowed-precise-terms` | Precise terms such as primitives, infrastructure, persistent/local/durable state, task frontier, knowledge graph, and queue are allowed when accurate. |
| `DECISION:application-website-docs-priority` | First-round work should prioritize the website landing page and docs; CLI help and command examples are secondary. |
| `DECISION:logo-restrained-technical-robot` | The robot may remain as a restrained technical mark, not a mascot-led voice. |
| `DECISION:color-preserve-navy-cyan-equity` | Preserve or deliberately evolve the existing navy/cyan equity; do not discard it casually. |
| `DECISION:direction-admired-reference-qualities` | Direction work should use owner-stated qualities from SQLite, Git, ripgrep, Tailscale docs, Fly.io, and Unix-style composability. |
| `DECISION:messaging-trust-relief-confidence` | Primkit should make capable developers feel trust first, with relief and confidence as secondary feelings. |
